# 表单控件与布局

## 选择字段控件

先确认业务值，而不是从数据库类型直接映射控件：

- 值表达什么业务含义，用户是在录入、选择、确认还是立即切换状态。
- 候选集合是否固定、是否便于同时扫描、是否来自远程实体查询。
- 是否存在单位、精度、范围、格式、依赖字段或不可逆影响。
- 用户录入频率、错误成本和是否需要比较候选项。

典型语义区别：

- 即时启停的独立设置可使用 Switch；随表单提交的确认或同意使用 Checkbox。
- 可同时扫描的固定少量选项可使用 Radio；固定但不宜展开的集合可使用 Select；需要搜索远程实体时使用可搜索选择控件。
- 数量、年龄、百分比、金额等不能仅因底层是 number 就共享同一种输入语义；保留各自的单位、精度和验证约束。

这些是判断示例，不是类型到组件的固定映射。项目组件命名不同时，先保持语义，再进行组件映射。

## 决定自然字段宽度

字段宽度由预期值长度、输入方式、业务含义和有效容器共同决定：

- 年龄、数量、百分比、短代码等使用与预期输入相称的宽度。
- 地址、描述、富文本或需要完整阅读的内容可以使用更宽区域。
- Label 或错误信息需要额外空间时，调整字段结构，不能仅以输入值长度计算整个字段宽度。
- 当前父容器只能合理容纳单列时，短字段可以随响应式布局扩展到整行。

## 组织字段

业务关系和填写顺序优先于填满行宽：

- 金额与币种、起止日期、城市与邮编等共同表达一个业务含义的字段可以组成字段组。
- 宽度恰好互补但业务无关的字段不得仅为消除空白而并排。
- 响应式折叠后保持字段组关系、阅读顺序和键盘顺序一致。
- 同一表单出现在 Dialog、Sheet 或独立页时，以各自实际父容器为布局基准，不只依赖视口断点。

完成检查：每个控件能解释业务操作，每个宽度能解释预期输入，每个并排关系能解释共同业务含义。
