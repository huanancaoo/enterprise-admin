Reference has two layers:

- **HTTP API**: fumadocs-openapi reads the business API snapshot `apps/api/openapi/openapi.json` and Better Auth's `apps/api/openapi/auth-openapi.json`. Authentication endpoints are grouped by the core or plugin tag, including Organization and Two Factor. Pages include request and response schemas, errors, and request examples.
- **TypeScript SDK**: Orval generates the business API client in `packages/api-client`. Authentication continues to use Better Auth Client. See the [SDK guide](./sdk.mdx) and [authentication architecture](../architecture/auth.mdx).

Pipeline:

```text
NestJS → openapi.json → docs build → API reference
Better Auth openAPI → auth-openapi.json → docs build → API reference
openapi.json → Orval → api-client → SDK docs
```

Run `pnpm api:openapi` to regenerate both snapshots without connecting to the database or Redis. The docs build reads these files, independently of runtime documentation endpoints.

In non-production environments, Better Auth also serves its Scalar reference at `/api/auth/reference` and JSON schema at `/api/auth/open-api/generate-schema`. Both HTTP endpoints are disabled in production; the static documentation remains available.
