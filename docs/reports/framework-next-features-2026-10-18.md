目录读取继续使用现有成员、角色和邀请事实，保持身份、组织的锁顺序。停用或撤权后清除失效缓存。操作日志候选采用独立的最小姓名投影，拥有 `audit:read` 即可使用，不要求 `member:read`，也不返回邮箱或完整成员资料。

定时任务以独立的平台身份和权限执行。计划列表使用 `platform.schedule:read`；创建和修改还需 `platform.schedule:manage` 及任务声明的权限，手动执行使用 `platform.schedule:run`。健康检查需要 `platform.monitor:read`，包含监控快照的运行记录也同时要求该权限。采用五字段分钟级 Cron 和 IANA 时区，停机期间不补跑；自动与手动执行共用同一计划的防重叠约束。停用仅停止自动触发，删除保留运行历史，运行中禁止删除。计划上下次时间按其时区显示完整日期和时分秒；历史运行起止时间明确按 UTC 显示，不把之后修改的计划时区当作历史快照。健康检查无需其他参数；“已完成”表示已取得监控快照，各服务是否可用以探针结果为准。

批量邀请使用单工作表、唯一 `email` 列的 XLSX 模板，最大 2 MiB、500 行，整批统一选择角色。已有成员、有效待处理邀请和文件内重复邮箱会跳过，其余成功或失败逐行记录。它沿用邮箱邀请，保留单条邀请的角色限制、七天有效期、有效待处理上限 100 和部署配额配置。原生邀请、配额记录、操作留痕、投递意图和报告在同一个普通任务事务内提交；已提交结果在重试时复用。创建邀请成功不等于邮件送达。即时投递与后台投递共享一次性领取，领取前重新检查取消和过期状态，结果未知时不自动重发；历史投递不猜测操作者或请求身份。

导出使用同一租户 Repository 和日志可见性投影，不额外暴露平台内部摘要。使用 Excel 流式写入和私有临时文件，完成后清理；单表超过 1,048,575 条数据时整体拒绝，不截断。容量错误在正常回调和 Worker 恢复路径都结算为 `rejected`。

脚手架只生成最小普通租户领域的列表、创建、删除；角色实际授予、可委派动作和三语由声明明确给出。写入前通过正式 Drizzle 检查已有 Schema 是否与迁移链一致，拒绝把其他未迁移变更混入新模块。生成结构与 RLS 迁移，不执行数据库迁移，也不向当前产品加入样例领域。使用方式见 [新增租户业务领域](../guides/create-domain-module.md)。
