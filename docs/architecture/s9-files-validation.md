## 实际边界与状态所有权

- `packages/contracts/file-path` 统一 trim、NFC、UTF-8 字节和非法段校验。文件名最多 255 字节、文件夹名最多 246 字节，完整用户相对路径（含 `/`）最多 512 字节。大小写区分，编码不能隐藏路径分隔符；部署根目录/基准前缀不占用户路径额度。
- 组织有效区为 `organizations/<UUID>/files/<层级>`，个人有效区为 `users/<UUID>/files/<层级>`；历史、回收站和暂存属于相应归属的内部受控区域。客户端提交文件身份和目标目录身份，实际地址由服务端生成。
- Local 使用已有私有根目录和区分大小写的文件系统，拒绝符号链接。S3 使用显式 endpoint、region、私有 bucket、基准前缀和凭据；生产模块不创建 bucket，也不自动切换存储。配置入口见 `apps/api/.env.example`，默认关闭，选择 `local` 或 `s3` 后明确配置所需字段。
- 空目录在 Local 中为真实目录，在 S3 中为零字节 `/` 标记。文件与目录的同级名称由数据库共同约束；对象存储原语本身不代表业务名称原子性。
- 上传发布等待完整流、目标实际字节、最终授权和数据库事务提交。版本、当前指针、容量与成功审计同事务提交；未发布对象不能通过内容 API 读取。
- 路径执行保存不可变对象计划，复制并校验后提交数据库定位和审计，再精确清理源对象。全部清理完成前不能报告操作已完成。真实 API 重启按同一操作身份继续，不能删掉后来复用源名称的新文件。
- 永久删除以实际对象删除、生命周期和容量结算、成功审计共同完成为依据。到期的被引用历史版本继续保留；重跑不重复释放容量或追加成功审计。
- Projects 附件和正文持有 `{fileId, versionId}`。库内覆盖不改业务引用；正文以内容语言分别保存，原 Projects 摘要仍为纯文本。正文/引用更新在业务事务内完成校验和保存。
- 引用位置经当前文件及 Projects 读取授权后展示；无 Projects 读取权限时只显示数量，不泄露名称和定位链接。回收条目详情不请求版本正文。
- 组织文件和个人媒体 API 每次读取和写入复核各自的当前身份与动作授权；组织文件另复核成员和组织状态。前端权限按组织与授权版本缓存；同一版本复用成功快照，授权版本变化重新读取。预览 Blob、正文和文件缓存随用户/组织/权限范围清理。
- Router 管组织、目录、已应用搜索/排序/页码和详情版本；Query 管服务端事实，Form/Editor 管草稿。CAS 冲突保留用户输入；已提交但刷新失败只能报告刷新失败，不能诱导重复写入。操作期间保留并禁用已授权按钮，使对话框完成后返回原焦点入口。

## RustFS 重新拉取与长度诊断

用户要求重新拉取后，固定 RustFS 1.0.0 的远端和本地 digest 一致。直接 S3 请求、官方源码及生产存储矩阵共同确认：RustFS 内部将末尾 `/` 目录标记编码为 `__XLDIR__`，占用单段 255 字节预算中的 9 字节，因此文件夹最多 246 字节。此边界与客户端流、空请求体和条件写入无关。[固定 1.0.0 源码](https://github.com/rustfs/rustfs/blob/1.0.0/crates/ecstore/src/bucket/utils.rs#L276-L299)。

| 实际请求                                | 固定版本结果        |
| --------------------------------------- | ------------------- |
| 246 字节普通文件和目录标记              | 200                 |
| 247/255 字节普通文件                    | 200                 |
| 247/255 字节目录标记                    | 400 InvalidArgument |
| 各段合规、完整用户相对目录路径 512 字节 | 200                 |
| 各段合规、完整目录标记 key 1024 字节    | 200                 |

另一个固定官方 preview 的单变量诊断结果相同，未改变项目版本记录。不能将单段超限失败推断为整体 1024 字节 key 不受支持；最终规则与完整测试按实际共同能力执行。

focused 诊断沿用现有 Vitest 配置：API 使用 `vitest.config.mjs --project api`，正式浏览器使用 `vitest.config.e2e.mjs`；先构建对应包。完整门禁还包括现有性能、RLS/数据库、翻译、边界、Storybook、生产构建和 OpenAPI/Orval 可重现检查，不能以 focused 成功代替整合结果。
