## 首批存储接口及约束

存储模块位于 `apps/api/src/files/storage`，只负责物理目录、写入、读取、复制校验及精确删除。地址由后续 Files 受控入口根据可信归属和已验证层级生成；该接口不承担成员授权、业务版本、配额结算或路径操作提交。

- `packages/contracts/file-path` 提供共享的 trim、NFC、UTF-8 字节长度及非法段校验。文件名上限 255 字节、文件夹名上限 246 字节，用户相对路径（含 `/`）上限 512 字节，大小写保持区分；编码/重复编码不能隐藏路径分隔符。校验区分所有目录段和最终文件段，两种存储采用实际共同支持的规则。
- 组织有效区位于 `organizations/<UUID>/files/<层级>`，个人有效区位于 `users/<UUID>/files/<层级>`；历史、回收站、暂存位于各归属的 `internal/<area>`。部署根目录/前缀不占用户相对路径额度。
- Local 要求已有私有根目录和区分大小写的文件系统；拒绝符号链接。写入使用独占创建，不隐式覆盖；复制验证目标实际字节及 SHA-256，源保留到执行器明确清理。
- S3 使用明确的 endpoint、region、私有 bucket、基准前缀和凭据，Path Style，无默认凭据链或存储自动切换。配置错误直接失败，生产模块不创建 bucket。基准前缀为完整归属与最大用户路径预留 key 空间。
- S3 使用零字节 `/` 目录标记；非根写入/创建必须有父目录标记。文件和目录共享的并发名称约束仍须由后续数据库命名预留协调，存储检查不证明跨种类原子性。
- 写入同时等待对象请求和实际输入流完整结束；声明长度与实际字节不符时不能产生成功事实。未知对象请求结果由后续持久化操作事实处理。
- `copy` 准备并验证新目标，不删除源。业务路径操作必须在数据库定位及成功审计提交后执行精确源清理；完整状态还需等待源清理完成，不能把复制返回当作业务完成。
- `removeDirectory` 只用于执行器精确清理已空的物理目录；它不代表业务只支持删除空目录。完整文件夹子树删除仍在本任务范围内。

已用直接 S3 请求和官方源码定位根因：RustFS 将末尾 `/` 目录标记在内部转换为 `__XLDIR__`，并在写入前从单段 255 字节预算中扣除该后缀的 9 字节。因此同一个普通文件名可写入 255 字节，而目录名称最多 246 字节。这是服务端显式规则，与客户端流、空请求体和条件写入无关。[1.0.0 源码](https://github.com/rustfs/rustfs/blob/1.0.0/crates/ecstore/src/bucket/utils.rs#L276-L299)及写入校验入口将超限名称拒绝。

诊断对照使用官方 `1.0.1-preview.16@sha256:0b3d45bbbc9eb73433ac48e4eb8374a460061ea1e4e952e25a3ef79796733617`，未改项目版本记录。stable 与该 preview 的相关目录编码和长度校验源码一致；两份固定官方镜像的直接 S3 结果一致：

| 单变量诊断                                                             | 两个固定镜像的结果  |
| ---------------------------------------------------------------------- | ------------------- |
| 246 字节单段普通文件及目录标记                                         | 均为 200            |
| 247 / 255 字节单段普通文件                                             | 200                 |
| 247 / 255 字节单段目录标记                                             | 400 InvalidArgument |
| 各段不超过 200 字节的 512 字节相对目录路径，含末尾标记 key 为 513 字节 | 200                 |
| 各段不超过 219 字节的整体 1024 字节目录标记 key                        | 200                 |

后一项原存储测试在准备 255 字节目录段时先失败，不能由此认定整体 1024 字节 key 不受支持。以上直接 S3 请求只用于定位，不替代生产模块和正式产品验收。诊断临时容器已清理。

用户已明确“去除 issue 这个规定，issue 不一定对，要根据实际情况”。Issue #25 因此只修改单段长度规定，保留完整功能、物理层级映射与其他边界；远端全文已与预期单处差异核对。当前实现按两种真实存储的共同能力区分文件名与文件夹名，拒绝超限目录，并保留 255 字节文件、512 字节完整路径和整体 1024 字节目录标记的真实生产接口验证，不删除断言或换用其他对象存储。更新后的两种存储矩阵全部通过。

Local/RustFS 共用 `tests/setup/file-storage-matrix.mjs` 中同一生产接口矩阵。Local 的每个用例由现有 Vitest 注册、调度和报告，Linux 进程只执行选中的同一模块用例；不增加测试应用、HTTP 路由或第二套测试运行器。物理字节、目录和对象检查独立读取实际文件系统/S3，不能以模块返回值代替存储事实。
