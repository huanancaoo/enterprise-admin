# 平台文件资源管理器

日期：2026-10-22。

状态：已实现并完成本机及自动化验收。实际环境、分层测试结果和未验证边界见[验收记录](platform-files-validation.md)。

## 问题与目标

平台后台缺少平台自有文件的统一管理界面。公告已经支持专用图片和附件上传，但上传结果没有接入可浏览的目录、版本、回收站和文件选择器。平台员工无法在文件库维护资源，再由公告复用这些资源。

本次建立平台自有文件库，完整对齐现有组织文件管理能力，并接通公告的上传、选择、引用与受众读取链路。平台任职和动作权限决定文件管理权；公告受众决定通过公告访问已引用内容的权利。

## 已确认的产品决定

| 决定         | 用户确认                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------- |
| 文件归属     | 平台自有文件，供公告、平台内容等功能使用                                                       |
| 管理能力     | 完整对齐 tenant 现有文件管理：目录、上传、搜索、预览与下载、移动与改名、版本、回收站、批量操作 |
| 操作授权     | 接入现有平台角色体系，按动作授权                                                               |
| 本次业务接入 | 同时接通公告，以完整业务链路验收                                                               |
| 存储策略     | 平台独立配置，初始容量 10 GiB、回收站 30 天、历史版本 90 天                                    |
| 引用保护     | 仍被公告引用的版本不得自动清除                                                                 |

10 GiB 为 10 × 1024³ 字节。上述容量及天数是新平台策略的初始值，不是对现有平台资源使用量的断言。

## 实施前的代码基线

- 平台页面登记与路由尚无文件管理页面，平台权限目录尚无文件与目录动作。
- 组织文件条目、版本、操作和引用以组织身份为边界；业务引用目前关联 Projects。
- 平台公告使用独立平台存储归属。现有上传返回的文件 ID 和版本 ID 都是平台资源 ID，尚无可独立演进的文件版本链。
- 公告正文图片和附件已经保存资源引用；公告媒体读取会校验公告发布状态及平台、全部组织或指定组织受众。
- 现有文件浏览组件可以由数据和回调驱动，但工作区装配直接依赖组织权限、组织身份及授权版本。
- Local/S3 存储、文件路径执行、版本消费、富文本内容读取和平台授权体系已有实现，应在对应职责层复用。

依据：[组织文件模型](../../packages/database/src/schema/files.ts)、[平台资源实现](../../apps/api/src/platform-resources/platform-resources.ts)、[公告服务](../../apps/api/src/announcements/announcements.ts)、[公告授权](../../packages/database/migrations/0074_platform-announcements.sql)、[文件工作区](../../apps/tenant/src/features/files/files-workspace.tsx)、[平台授权 ADR](../adr/0002-platform-assignment.md)。

## 功能与业务语义

### 文件工作区

1. 平台员工从平台菜单进入文件库，按目录浏览文件和文件夹，使用目录树与面包屑定位。
2. 当前目录展示直接子项，支持服务端分页、排序、搜索及搜索结果定位；刷新和浏览器前进后退保留已应用的导航状态。
3. 支持多级和空文件夹；上传目标为当前目录，目录层级对应所选 Local/S3 存储中的受控路径。
4. 支持真实文件选择和拖放上传，显示进度与结果；失败保留待上传文件，按现有文件操作语义处理结果未知和明确重试。
5. 文件详情展示元数据、当前版本、历史版本和业务引用；支持预览与实际下载。
6. 同名覆盖创建新版本。已保存的公告引用仍指向原版本，只有公告编辑者明确替换并保存后才切换引用。
7. 支持文件和文件夹子树改名、移动、回收、恢复及永久删除，遵守同级重名、目录循环、版本冲突和引用约束。
8. 批量操作提供逐项结果，准确呈现部分成功；不能把一个条目的成功表示为整批成功。
9. 沿用项目已有语言、RTL、键盘、焦点管理及无障碍要求。

### 平台授权

- 平台文件和目录动作登记到现有平台权限目录，角色管理可授予对应动作；内置超级管理员按现有规则获得代码登记的全部动作。
- 浏览、上传、修改、回收、恢复和永久删除按对应动作校验。按钮与路由使用同一授权事实，服务端每次请求重新校验当前 Session、账号、任职和角色权限。
- 现有自定义角色不会因具有公告管理权而自动获得全部文件管理权。公告编辑中的文件选择需要文件读取权限，新增上传需要上传权限。
- 文件写入在最终提交前复核权限，授权与元数据、容量和成功审计的提交规则保持一致。
- 平台文件授权不使用组织成员身份。租户用户通过公告读取文件，不因此获得平台文件库的列举、搜索或操作权限。

### 公告消费

- 公告编辑支持上传新图片或附件，也支持从平台文件库选择已有文件及版本。
- 保存公告时校验选定引用，将正文、附件和引用关系作为一致的业务变更保存。
- 公告预览和读者读取继续按各自现有授权入口执行；已发布公告的媒体访问保持原有受众边界。
- 公告正文与附件固定引用文件版本。文件覆盖、改名或移动不会悄悄改变已保存公告的内容字节。
- 活跃业务引用阻止回收或永久删除相关文件及包含它们的目录。被引用的历史版本即使到期，也继续保留。
- 从公告移除或替换引用后，文件版本重新按其生命周期和既定到期时间参与维护；不另建一套清理语义。
- 文件详情的引用数量与可见业务详情分开处理；没有公告管理权限的文件操作者不得借引用详情读取公告草稿内容。

### 容量与保留

- 平台文件库拥有独立容量账本与策略，默认容量 10 GiB、回收站保留 30 天、历史版本保留 90 天。
- 策略在平台设置中维护，沿用平台设置读取和修改授权。修改采用现有版本冲突及审计规则。
- 容量计量、预留、暂存、历史与回收站占用沿用现有文件管理语义；拒绝超额上传不会删除已存在内容。
- 新生成的历史版本或回收条目使用当时策略确定期限。调整策略不重写既有条目的期限，也不直接删除文件。
- 自动维护遵守引用保护，并复用现有执行、重启恢复和结算规则；物理对象清理及容量结算完成后才能报告清理完成。

## 实施方案

### 1. 平台文件领域与持久化

为平台自有文件建立明确的目录、条目、版本、操作、容量策略及公告引用模型。平台文件库使用独立的物理存储归属，避免自由文件名与任务资源 ID 发生碰撞；组织文件继续保持现有组织隔离。

平台数据访问遵循现有平台授权 ADR：受限数据库入口校验当前平台动作，并为新表声明最小权限、RLS、约束和事务审计。迁移加入唯一迁移链，已执行迁移保持原样。

仅抽取两种文件归属确实共用的存储执行与生命周期算法；组织授权、平台授权和各自业务引用保留在所属领域。具体内部接口在实现时围绕已经存在的操作边界确定。

### 2. 现有公告资源迁入

盘点既有公告媒体及引用，建立确定性的目录和版本映射，保留内容字节、文件名、原引用身份与公告受众。目录映射在写入前验证同级重名和路径约束。

迁移范围只包含公告资源；任务导出结果继续由任务领域管理。迁移完成后公告统一使用平台文件版本与引用模型。旧资源到新模型的映射、字节校验、容量初始化和公告可读性共同构成迁移验收条件。

迁入数据按实际占用初始化容量；若既有数据超过默认配额，保留已有内容并按现有超额规则拒绝新增占用，等待管理员调整策略。

存储归属切换前，已在旧服务执行的文件操作和公告迁入必须全部恢复、结算完成，随后停止旧服务再执行迁移，防止新旧执行器同时写入。0092 直接升级生成的全新迁入计划可由新服务执行；旧迁入已部分完成或仍有有效执行租约时，迁移明确失败并回滚，先由旧服务完成恢复再重试。新服务启动时完成迁入及字节校验后才接受文件请求。

### 3. 平台 API、权限与操作执行

新增平台文件与目录、内容读取、上传及覆盖、操作状态、批量、引用、版本、回收站和存储策略入口。复用现有契约中的文件形状及通用命名约束，归属和授权由各入口确定。

以源契约生成 OpenAPI 和客户端，审查生成差异。平台动作目录、数据库动作目录、角色界面和审计事件同步更新。文件管理读取与公告受众读取分别校验各自的业务权利。

### 4. 管理页面与公告接入

将两端共用的文件浏览、目录、详情、选择和操作交互放入符合项目依赖边界的共享层；应用装配负责自身路由、身份、授权和客户端调用。

完成平台页面登记、导航及独立策略表单；公告编辑器接入平台文件上传和版本选择。公告读者通过现有公告授权路径获取选定版本内容。

### 5. 验收与回归

采用下述既有测试边界逐段验证，再运行受影响检查与完整业务回归。每项结果记录实际运行环境、命令、通过或失败及未验证范围；编译或构建成功不代替业务验收。

## 已确认的验收边界

优先通过现有两个公开边界验证用户行为，不为内部方法单独建立大量实现绑定测试。

| 边界          | 必须证明的行为                                                                                                                                   |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 正式 HTTP API | 平台动作授权与撤权、平台和组织隔离、目录及版本生命周期、容量预留与结算、引用删除保护、公告受众读取、批量结果与操作恢复                           |
| 正式浏览器    | 文件库创建目录与上传、预览及下载、覆盖形成新版本、公告选择固定版本与发布、目标受众实际读取、非受众拒绝、回收恢复及引用阻塞、策略变更、三语与 RTL |

两类边界复用仓库已有 API 与浏览器测试入口。Local 与项目固定 S3 测试后端均覆盖关键文件生命周期和公告消费链路，实际下载字节与期望内容比对。

数据库迁移另验证旧公告资源迁入、重复迁移、最小授权和 RLS；共享界面变化补充必要组件交互与无障碍检查。已有组织文件、Projects 固定版本引用、个人头像和任务导出构成受影响回归边界。

主验收路径：平台角色获得所需动作 → 创建目录并上传文件 → 公告选择该版本并发布 → 目标受众读取相同字节 → 文件覆盖生成新版本 → 原公告仍读取旧版本 → 引用阻止删除 → 显式替换或移除公告引用后按文件生命周期处理。

## 范围边界

本次不包含跨租户管理组织文件、个人文件库、匿名公开文件链接、独立文件或文件夹 ACL，以及新的平台内容业务。已存在的组织文件、个人头像与任务导出不因增加平台文件库而改变归属或授权。

提交、推送、PR 和部署分别遵循仓库 Git 协作规范及用户授权，不由本文推导发布授权。
