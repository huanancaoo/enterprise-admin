## 已确认范围

用户要求完整实现：自托管发行与恢复、业务模块开发指南、运行观测与告警、业务通知、数据导入导出、通用任务中心、个人账户安全中心、对外系统集成。

交付目标是 Docker Compose 发行包及安装、升级、回退、备份恢复验收。部门/团队、数据范围权限、SSO/SCIM、审批工作流和订阅计费不属于本次范围。范围来自本会话用户的明确回答。

## 已确认首版业务规则

以下首版规则已经用户逐组确认；当前实现与验收状态分别记录。

| 能力         | 建议规则                                                                                                                             | 必须确认的原因                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 导入         | Projects 为完整参考；CSV/XLSX；列为 `name`、`description`、`contentLocale`；仅创建新项目；整批校验通过后一次提交，错误返回行号与字段 | 是否更新、按什么键更新、是否接受部分成功会改变业务事实与事务语义           |
| 导出         | 导出本组织当前已应用筛选下的全部匹配项目，使用请求的内容语言；CSV/XLSX；由 Worker 执行并产生受授权下载的结果                         | 当前页与全部匹配记录不同；译文、富文本、附件的导出范围必须明确             |
| 通知         | 首先接入导入/导出完成与失败，收件人为发起人；站内通知含未读/已读与偏好，业务邮件按用户偏好投递；认证邮件继续遵循原规则               | 自动通知谁、发送哪些渠道，会改变用户可见行为与信息披露范围                 |
| 任务中心     | 展示新 Worker 业务任务与现有 Files 操作的历史、状态、结果；保持各来源自己的生命周期；成员查看本人任务，owner/admin 可查看组织任务    | 本人或组织可见会改变权限和结果下载范围；Files 生命周期不能被新任务状态覆盖 |
| 外部调用身份 | 凭据绑定现有用户与一个明确组织；资源动作权限受凭据范围和当前成员角色共同限制；支持到期与撤销；组织停用/撤权对后续调用生效            | 用户凭据、组织凭据、独立服务身份需要不同的授权与审计模型                   |
| Webhook      | 订阅 Projects 变更和业务任务结果；具备签名、持久投递、重试和投递记录；事件范围与授权归属明确                                         | 投递给外部系统的字段、事件范围和授权归属必须先确定                         |
| 账户安全     | 接入原生密码/邮箱变更、会话列表与撤销；修改密码撤销其他会话并保留当前会话；邮箱变更完成原生验证，用户 ID 保持不变                    | 密码变更后的会话存续、邮箱验证方式是身份行为，不能由 UI 自行决定           |
| 发行与备份   | 使用维护停写方式取得数据库、Files 对象与 Redis 持久状态的一致备份；恢复使用部署方提供的密钥配置；在新专属数据卷验收恢复              | 在线与停写备份具有不同的一致性约束；不能只恢复 SQL 就宣称整个系统可恢复    |
| 开源文件     | 按归档架构建议使用 Apache-2.0；补贡献、安全报告、变更记录与发行说明                                                                  | 归档建议没有自动授权项目采用某个许可证；实施前 API 标为 UNLICENSED         |

导入建议列参考当前 [CreateProjectSchema](../../packages/contracts/src/index.ts)；附件、分语言富文本正文和其他语言译文不包含在上述首版数据文件中。若用户需要可无损迁移全部项目内容，需要另行明确文件格式及对象引用规则。

原始 CSV/XLSX 文件最大 10 MB（10,000,000 字节）；XLSX 必须恰好一张工作表，多个工作表整批拒绝并生成文件级错误报告。传输使用 base64，只有导入路由提高 JSON 容量，其他业务 JSON 保留原上限。

CSV 字段校验报告的行号指原 CSV 文本中该记录的起始行；空行和带引号字段内的换行都保留在位置计算中。XLSX 使用工作表原始行号。这一定义已由用户明确确认。

API HTTP 启动后自动运行业务投递器。邮件按当前偏好，仅向仍是组织成员的任务发起人账户邮箱发送完成/失败提示与任务链接。Webhook 仅向组织管理员配置的订阅 URL 发送事件 ID、类型、组织/资源 ID、时间及状态、数量、错误码或变更字段摘要，不发送项目名称、描述、正文和附件。该范围来自用户对具体载荷与目的地的明确批准。

## 接入路径

1. 完成身份与任务结果的公开契约及领域规则，再从 contracts 生成 OpenAPI/Orval。认证操作继续接 Better Auth 原生能力。
2. 在现有 Worker 上接入 Projects 导入/导出，执行时重查当前授权，数据修改走 TenantTx；持久业务事实、幂等回执、任务结果与审计保持一致。
3. 接入通用任务查询与结果下载，再加入通知和 Webhook。外部邮件与 HTTP 投递不在业务数据库事务内等待网络完成。
4. 用正式生成客户端接入两个后台的账户安全，以及租户后台的任务、导入导出、通知与外部集成界面。表单按 [表单规范](../agents/forms.md)；交互按业务任务选择现有组件。
5. 接入 HTTP/Worker 关联日志、traces、metrics 与本地告警验证，审计继续是独立的业务事实。
6. 完成 Files 启用的 Compose 发行、升级、真实目标版本回退、备份恢复；给同一套不可变产物执行验证、扫描、SBOM 和发行证据生成。
7. 补完整模块、安装、升级、恢复与贡献指南。所有完成标记必须来自实际对应验证，不通过编写文档把未验收事项标为完成。

## 已确认公开测试 seam

用户已确认的 Worker 基础设施 seam 继续沿用；新增业务能力的 seam 列在这里。确认后按一条失败测试、一个最小实现的纵向切片推进，不批量编写猜测行为的测试。

| 能力           | 公开测试 seam                                                                      | 关键可观察行为                                                                       |
| -------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 账户安全       | 原生认证 HTTP与两个后台的真实浏览器入口                                            | 新邮箱验证；密码变更后的新旧会话访问；会话撤销；失败保留输入；不创建第二套认证事实   |
| 导入导出与任务 | 上传/任务 HTTP → 正式生产者 → 真实 Redis → 独立 Worker → 任务/项目 HTTP 与结果下载 | 确认的提交原子性；未知提交结果；重复请求；处理中撤权；跨组织拒绝；下载字节与项目读回 |
| 通知           | 业务任务终态 → 正式通知 HTTP → 真实页面；业务邮件通过 SMTP/Mailpit                 | 正确收件人；幂等；未读与已读持久化；通知偏好；跨用户/组织隔离                        |
| 外部调用身份   | 凭据管理与正式业务 HTTP                                                            | 当前成员权限与凭据权限共同限制；到期、撤销、成员移除、组织停用生效                   |
| Webhook        | 正式订阅/投递 HTTP 与本地外部接收端                                                | 正确事件、签名和字段；重试与重复投递；投递记录；撤销订阅生效                         |
| 观测           | 正式 HTTP/Worker 运行及本地 telemetry/metrics 接收端                               | 请求与任务关联；错误/积压指标；告警规则触发；日志不包含认证秘密                      |
| 发行与恢复     | 现有 release project、正式发布/备份/恢复 CLI 与正式业务 HTTP/浏览器                | 首装、升级、Files 持久性、实际 Worker 回退；恢复后的文件字节、业务事实与权限隔离     |
| 二次开发       | 完整模块开发指南与独立照做验证                                                     | 不绕过 TenantTx/RLS，不手写重复 DTO，不建立第二套状态来源；文档/链接/格式检查        |

主要使用现有 `tests/api`、`tests/e2e`、`tests/release` 和 Storybook/MSW 入口。普通本地开发优先使用现有服务；发行、恢复及故障测试的隔离环境应有明确用途，并仅清理该次测试资源。
