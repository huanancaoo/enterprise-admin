# S8 邀请管理验收（#14 / #15）

## 实现边界

邀请创建、列表、接受、拒绝和取消继续使用 Better Auth 原生 API。重发在同一原生创建入口中执行受控发送，保持原邀请 ID、角色和过期时间。独立投递 attempt 仅保存发送事实，不承载邀请生命周期。

组织锁串行化邀请、成员、角色及组织状态写入。接收身份或管理权限先于邀请终态判断；接受会重新检查原邀请人的可授予资格。只有当前已验证的同邮箱用户可以接受或拒绝；停用组织允许接收者拒绝。确认页 GET 不加入组织，终态重放不重新创建成员。

创建与重发共用滑动一小时配额：组织同邮箱固定 5 次；组织、操作者和可信 IP 默认分别为 100、50、100，可通过 API 环境变量配置。IP 来源为 Express 的受信任代理配置，持久化时采用 HMAC。重发冷却 60 秒，有效期为创建起 7 天。

邀请和 pending attempt 先共同提交，再由当前请求等待 SMTP。发送开始前记录 unknown；明确连接失败或 SMTP 拒绝记录 failed，SMTP 接受记录 smtp_accepted，接受后连接中断等无法证明结果的情况记录 unknown。禁用 SMTP 库自动重新排队。SMTP 接受不代表进入收件箱。

邀请提交后的发送或结果持久化故障不改变已提交创建结果；attempt 保留已记录事实，稳定日志仅记录事件和 requestId。SMTP 结果与对应投递审计共同提交。列表读取失败独立展示，不把成功创建变成表单失败。

界面使用中文、英语、阿语 catalog 和逻辑方向布局。邀请确认页面禁用 Referer；登录回跳仅接受产品已有的邀请页路径。生产代理或 CDN 的访问日志还需按部署日志规范处理邀请路径，当前本地验收不能证明生产边缘日志配置。

## 验证入口与证据

- `tests/api/invitations.test.mjs`：真实原生 HTTP、PostgreSQL、限流、权限、并发、终态、SMTP DATA 后断连及结果持久化故障。
- `tests/api/email.test.mjs`：真实 Mailpit SMTP 接受，已有个人／组织／平台语言优先级、阿语邮件正文与 HTML RTL。
- `tests/e2e/invitations.test.mjs`：真实 Chromium、API 和数据库；失败投递提示、冷却错误、键盘取消、停用组织阿语 RTL 拒绝。
- `tests/e2e/email-ui.test.mjs`：实际邀请邮件链接、确认页只读、登录及接受后的组织进入流程。
- 双轴审查基点为 `31c5fe88`，审查邀请权限、事务时序、稳定审计事件、表单和迁移规范。

## 实际验证结果

- 邀请 API 聚焦测试：17 项通过，包含真实 SMTP 未知结果和结果持久化故障。
- 邀请浏览器聚焦测试：2 项通过；完整浏览器集合 37 项通过。
- 数据库迁移与隔离集合：17 项通过；新增表已纳入迁移验收清单。
- Compose 验证通过：镜像迁移、数据卷重建持久化、重复迁移及错误身份失败退出。
- 完整 `pnpm verify` 门禁通过，共 313 项测试；包含 lint、类型、i18n、内容、单元、HTTP、Storybook、浏览器、Schema、数据库、构建和 API 生成一致性检查。

## 双轴审查结果

- Standards：Schema 工厂移出组件；手写授权迁入生成的 custom migration；内部调用的投递错误日志使用事务已捕获的 requestId。无未解决规范问题。
- Spec：授权前的邀请终态／存在性区分已消除；提交后投递持久化错误保留原生创建结果；邀请与邮件稳定事件已补齐。无未解决规格问题。

测试环境的邮箱账户、组织和故障注入仅存在于测试 PostgreSQL；正常开发环境和生产迁移未执行。迁移 `0025` 新增投递与限流记录，custom migration `0026` 授权并更新原生写入约束及审计映射，必须通过项目唯一 migrator 串行发布。
