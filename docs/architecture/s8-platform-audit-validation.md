# S8-14 平台跨组织审计验收

对应 [Issue #22](https://github.com/huanancaoo/enterprise-admin/issues/22)，验证日期为 2026-10-02。本记录覆盖该功能与受影响的平台回归；S8 整体发布、全量业务组合和规定规模的性能验收仍属于 #24。

## 查询与权限

平台管理员和审计员以有效任职、权威 Session 和当前 Session 的 TOTP assurance 查询。API 复用已确认的 app_runtime 连接池，只执行参数化 list/get 固定函数。函数由 NOLOGIN platform_executor 持有，固定 search_path、启用 row_security，撤销 PUBLIC、历史 platform_runtime 和部署账号执行权限。app_runtime 不能直接查询运营投影视图、任职审计或范围判定辅助函数；Projects 和租户审计的原有 RLS 不放宽。

获准数据包含明确事件目录中的组织成员、邀请、角色、组织设置和平台运营事实，以及部署 CLI 已记录的 platform_assignment_audit。查询不纳入 Projects 事件、业务内容或未知事件。两个事实源使用 event/assignment 前缀标识，避免 UUID 跨表碰撞；不复制或改写已有任职审计。

列表与详情统一返回 scope、目标组织、操作者类型与 ID、脱敏邮箱、资源标识和结果。任职记录保留原角色、新角色及 changed/no_change 语义。原始 metadata、内部理由、部署操作者字符串、认证记录和完整邮箱不进入投影。平台 MFA 事件记录真实的当前 Session TOTP 验证，不把普通注册、密码登录或 MFA 启用标记当作第二因素成功事实。

## 目的、窗口与分页

每次 list/get 请求都携带 1–500 字符的 purpose。成功返回前在同一数据库事务追加一条私有 platform.audit_queried/platform.audit_viewed，记录目的和查询范围或事件标识。审计失败返回 503，不返回已读到的受限结果；不为每个结果行生成访问审计。

筛选支持组织、操作者、事件、起止时间与结果。默认查询最近 30 天，窗口最多 90 天，拒绝未来结束时间。默认时间和时间校验由数据库的同一时钟决定；0034 已应用后发现默认时间权威不一致，通过新增 0035 修正，保留迁移历史。

按时间和带来源的事件 ID 倒序稳定分页，使用 HMAC 签名游标绑定时间窗口、筛选与页大小。游标保留数据库时间精度和首次查询的上界，分页期间新写入不进入该查询。修改筛选、页大小、篡改签名或使用租户审计游标均被拒绝。

页面先填写目的再读取，非目的筛选写入 URL；浏览器历史恢复筛选并重建分页与详情状态。目的只在本页内存中保留，每个请求重新携带，刷新后重新填写。失败保留目的与筛选，提供显式重试；撤权后清理平台查询缓存并跳转拒绝页面。

## 2026-10-17：通用 DataTable 与页码分页

平台组织、用户和审计目录统一使用 `@workspace/admin/data-table`；Router 持有已应用筛选与页码，Query 获取服务端当前页，DataTable 提供统一的加载、错误、空态、视图及分页控件。组织保留姓名/slug 搜索、状态筛选及原有四个排序字段；用户保留目录搜索；审计保留业务筛选与详情（读取目的已在下述后续调整中改为可选），排序固定为时间和完整事件 ID 倒序。

`0061_platform-audit-page-pagination.sql` 替换旧游标函数，HTTP 查询参数改为 `page`（默认 1）和 `pageSize`（默认 20，最大 100）；响应为 `items/page/pageSize/total/window`。精确总数与当前页来自同一个 SQL 语句快照，越界页保留真实总数。默认最近 30 天、最长 90 天及未来时间拒绝仍由数据库执行；后续翻页传回响应的 `window.from/to`，保留微秒边界，不经过 JavaScript Date 转换。该窗口是时间过滤范围，不是长期数据库快照；后来补记到范围内的历史事件仍会反映在查询中。

每页继续重新检查当前有效 Session 和平台任职、执行脱敏并追加一次私有访问审计。`0062`–`0063` 通过最小 executor 列权限将本次读取事实的发生时间设为查询完成时刻，使其不进入本次冻结的窗口。读取目的只留页面内存，不进入 URL。租户审计的游标协议保持原实现。

`0064` 保留所有函数的固定搜索路径，将同一事件目录提取为受限不可变函数；列表与 RLS 使用固定 scope 实参，在规划期求得常量目录后逐行匹配。原分类函数委托此唯一目录，不增加任何事件或运行角色执行权限。十万次纯分类的只读计划验证了目录调用被替换为常量数组；最终性能以真实 HTTP 压测为准。

本次验证：审计 HTTP 11 项、三个平台列表浏览器流程 23 项、三个列表与公共 DataTable 的 Storybook 97 项全部通过；Lint、TypeScript、三语目录、前端构建、认证 Schema 漂移及 OpenAPI/Orval 可复现性检查通过。固定 100 组织、10000 用户、100000 条审计、90 天范围、并发 20、每个端点 200 样本的现有性能测试通过，审计首页 P95 小于 1000 ms；未以此宣称任意深页均达到同一延迟。当前本机浏览器已验收第 1 页直达第 3 页且总数保持一致。新增迁移已应用到本机开发库。

## 2026-10-17：紧凑筛选与可选读取目的

审计筛选统一放入 DataTable 工具栏的筛选 Popover；关闭时只占一行工具栏，组织、操作者、事件、结果和时间范围保留原有能力。空集合或零结果时仍显示筛选入口。输入在显式应用后更新 URL 并回到第 1 页；取消或关闭不改变当前查询。

按用户确认，进入页面和刷新后直接加载，无需填写目的。读取目的作为筛选面板中的可选备注，只留本页内存；列表和详情均允许缺省，填写时最多 500 字符。迁移 `0066_optional-platform-audit-purpose.sql` 将缺省或空白理由保存为 NULL，不生成替代理由。当前会话、平台任职、脱敏、事件目录和最长 90 天的范围规则继续执行，每次列表及详情读取仍必须成功追加私有访问审计才返回数据；审计写入失败继续返回 503。

本次验证：审计 HTTP 12 项、审计浏览器流程 6 项、审计与公共 DataTable 的 Storybook 45 项通过；全仓 Lint、类型检查、三语目录检查、平台构建、认证 Schema 及 OpenAPI/Orval 可复现性检查通过。本机开发库已应用 `0066`，当前浏览器已确认无需目的即可打开列表和详情。

## 2026-10-17：操作日志与标准 DataTable

平台菜单、面包屑、页面标题与详情统一称为“操作日志”。页面直接使用通用 DataTable 的事件代码搜索（精确匹配、最长 120 字符）、结果单选筛选、清除筛选、列显示与页码分页；组织 ID、操作者 ID 与 UTC 起止时间保留在工具栏高级筛选中。各条件通过 Router 管理，提交搜索或修改条件回到第 1 页；高级筛选未修改的时间边界保留数据库原始精度。

按用户确认，读取目的已完全从本页面、契约、列表/详情 API、生成客户端与固定函数参数移除，取代上节的可选备注规则。迁移 `0067_remove-platform-audit-purpose.sql` 删除旧函数签名，创建没有目的参数的新入口，保留 executor 所有权、固定搜索路径、RLS 及原调用权限。每次列表或详情读取仍在返回前写入私有访问事实，`reason` 固定为 NULL；操作者、请求、查询范围或目标事件 ID 继续记录，写入失败仍返回 503。已有历史记录与敏感邮箱读取目的不受此次字段删除影响。

本轮验证：操作日志、用户及平台权限 HTTP 测试 26 项，真实浏览器 6 项，操作日志及公共 DataTable 组件 44 项全部通过。全仓 Lint、类型检查、三语目录、API/平台构建、认证 Schema 和 OpenAPI/Orval 可复现性检查通过。`0067` 已应用到本机开发库，当前本机页面已确认新名称、标准工具栏及无读取目的输入。
